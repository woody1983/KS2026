Executive Summary

Project Purpose

The E Ola! Learner Analytics System represents a transformative initiative designed to operationalize Kamehameha Schools' distinctive educational philosophy through data-informed practice. This comprehensive web-based platform enables systematic collection, analysis, and visualization of student progress across 14 interconnected learner outcomes that constitute the E Ola! framework, organized through the powerful Native Hawaiian Forest metaphor.

Unlike conventional student information systems that prioritize administrative efficiency over pedagogical insight, this system is architected from the ground up to serve the specific mission of nurturing Native Hawaiian learners who are grounded in cultural identity, equipped with 21st-century skills, and committed to community stewardship [1].

Core Value Proposition

Quantification of Intangible Outcomes

Multi-method measurement of cultural identity, servant leadership, and well-being through triangulated data sources

Innovation Adoption Analytics

Implementation fidelity tracking, barrier identification, and outcome correlation for PBL-by-Design

Data Architecture & Privacy Compliance

FERPA Regulatory Framework

Education Records Definition & Scope

FERPA defines education records as records directly related to a student maintained by an educational agency or institution. This encompasses virtually all data processed by the analytics system, including academic performance, behavioral records, assessment results, and E Ola! indicators.

Cloud Deployment Compliance

Azure deployment with contractual provisions maintaining KS control meets FERPA requirements for records maintained by parties acting for the institution.

Disclosure Limitations & Parental Rights

Legitimate Educational Interest

Role-based permissions with automated access logging

Parental Inspection & Review

Parent portal with 45-day response workflow

Amendment Requests

Routing to appropriate officials with tracking documentation

Dynamic Data Masking Implementation

DDM applies masking rules dynamically at query time, ensuring users see only data appropriate to their role while maintaining single authoritative source. This approach never modifies stored data—all masking occurs at query execution.

Key Benefits

  • Authorized users access complete original data when appropriate
  • Masking rules modifiable without data migration
  • Aggregate functions operate on underlying values

Implementation Levels

Column-level DDM Sensitive field masking
Row-level security Record filtering
Contextual rules Variable masking

Role-Based Masking Configuration

User Role Masking Configuration Example Application
Individual Student/Parent Complete records for self only; all others fully masked Student sees own full record; peers invisible
Classroom Teacher Full detail for current students; masked identifiers for historical comparison Teacher sees assigned students' complete profiles; prior year performance as "Student A," "Student B"
School Leader Statistical aggregates with individual masking; drill-down authorized for specific purposes Principal sees grade-level distributions; individual identification requires documented justification
Researcher Anonymized identifiers with cryptographic hashing; statistical noise for small cells Research ID enables longitudinal tracking without re-identification risk
